## Known baseline failures

### Test failure

`apps/web/src/app/page.test.tsx` expects `/api/auth/login`, while the component renders a URL containing a dynamic timestamp query parameter. This is also reported by the React purity lint rule because `Date.now()` executes during render.

### Lint failure classes

- Explicit `any` types.
- State updates initiated synchronously from effects.
- Functions referenced before declaration.
- Impure render-time calls.
- Unescaped entities.
- Unused variables and imports.

### Dependency audit

- High severity advisories in the `undici` dependency chain used by GitHub Actions packages.
- A moderate PostCSS advisory in Next.js' bundled dependency tree.

No automatic audit fix was run because the suggested forced change is breaking and would violate the preservation contract.

## CI policy introduced by Step 0

The repository CI must run four independent, strict jobs:

1. Build the CLI, GitHub Action, web application, and VS Code extension.
2. Run all available workspace tests.
3. Run the web ESLint configuration.
4. Audit production dependencies at the high-severity threshold.

Independent jobs ensure that one known failure does not hide results from the other quality gates. Failures remain visible until the corresponding remediation step fixes them.

## Commit policy for remediation

- Use Conventional Commits.
- Keep security, database, integration, UI, and tooling changes in separate commits.
- Stage explicit paths only; never use broad staging while user-owned working-tree changes are present.
- Each functional fix must include or update a regression test in the same commit.
- Do not mix generated artifacts with source changes unless the package distribution contract requires them.
